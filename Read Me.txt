A Windows-PowerShell-style terminal you can talk to. It is read-only by default: it only changes things when you
ask (updating itself, starting a game or a program, saving a report).

HOW TO OPEN:   double-click  start.bat     (Python 3 must be installed)

HOW THE FOLDER IS ORGANISED
  Jarvis\
    start.bat        the only file you need to open
    Read Me.txt      this file
    All Process\     everything else is in here: you do not need to touch it
        launcher.py     the start screen with the menu (start.bat runs it)
        pwsh.py         the file that really runs (and that Jarvis checks and updates by itself)
        src\            the code, split into 23 modules: this is where you work
        build.py        the "glue" between src\ and pwsh.py (the menu runs it for you)
        jarvis_update\  Jarvis's logs, heartbeats and data (re-created if missing)
        backup\         safety copies (created when needed)

THE START SCREEN (start.bat)
  Black background, terminal font. Jarvis greets you by "typing" letter by letter, like a machine, then the menu appears:
      1. Install Guard   installs the always-on guard: it starts with Windows even if Jarvis is closed
      2. Delete Guard    removes the guard
      3. Proceed         aligns the modules and opens Jarvis normally
      4. Exit            quits
  Choose with the up/down arrows + ENTER, or press 1-4 (Esc = exit). Press any key while it is typing to skip the animation.
  Every time you choose Install Guard, Delete Guard or Proceed, the menu first checks that src\ and pwsh.py are aligned
  (see below). If there is a syntax error, Jarvis does NOT start and tells you the file and the line.

HOW TO CHANGE THE CODE
  1) edit a file in All Process\src\   (for example 14_news.py for the news, 20_voice.py for the voice)
  2) double-click start.bat and choose Proceed  ->  pwsh.py is rebuilt automatically.
     If there is a syntax error, it tells you the file and the line, and NOTHING broken is started.

WHEN JARVIS UPDATES ITSELF ("implement jarvis", data update, etc.):
  at the next start the changes are copied back into src\ (a backup goes to backup\).
  If you changed src\ AND Jarvis changed pwsh.py at the same time, nothing is touched and you are told how to choose
  (from a terminal window inside All Process\):
      python build.py --build   (keep src\)       python build.py --pull   (keep pwsh.py)
  Useful:  python build.py --check   tells you whether everything is aligned

IF WINDOWS SAYS "UNKNOWN PUBLISHER" (SmartScreen):
  this is the standard warning for downloaded files; it has nothing to do with the code (read it: it is plain Python).
  Before extracting: right-click the zip -> Properties -> tick "Unblock" -> OK. Or in PowerShell:
  Get-ChildItem -Recurse "C:\path\to\Jarvis" | Unblock-File

SCREEN WATCH (Windows only):  "watch" tells you when someone may be looking at your screen
  (RDP, VNC, TeamViewer, Zoom and similar). It only READS what Windows reports (sessions, connections, processes,
  window titles). Type:  help watch      Its only file is its settings file, jarvis_update\screenwatch.json

ALWAYS-ON GUARD (works even when Jarvis is closed):  from the menu, "Install Guard" (once), or from Jarvis:  "watch guard on".
  It puts a file in your Windows Startup folder that runs the same check in the background, with no window.
  If Jarvis is open, Jarvis gives the warning (and pauses) and the guard stays silent: never two windows.
  To remove it: menu "Delete Guard", or from Jarvis "watch guard off".
  Manage it from Jarvis:  watch guard | on | off (removes everything) | start | stop
  The file:  %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\JarvisScreenWatch.vbs
  Windows limit: programs in Startup begin a few seconds after the desktop appears, not before.

FIREFOX SHIELD:  while someone is watching your screen, Firefox is dealt with at once. THE DEFAULT SINCE 3.1.3 IS
  "kill": as soon as the guard sees remote access (RDP, VNC, TeamViewer, Zoom, screen sharing...) Firefox is
  TERMINATED immediately, WITHOUT asking you to save anything, and if it is opened again it is closed again every
  0.05 s for as long as the viewer is there.
  watch shield                    status (on by default)
  watch shield kill | hide | minimize | close | off
        kill     = ends the program at once (default)       hide     = only hides its windows (nothing is lost)
        minimize = minimizes it                             close    = closes it politely, so it can ask to save
        off      = shield disabled
  watch shield show               puts hidden windows back at once (even if the guard has died)
  watch shield add / del <program.exe>           other programs to protect (for example chrome.exe)
  Heads-up: with "kill", Firefox gets no chance to save. Its own session restore usually brings the tabs back, but
  anything else that was not saved (for example text typed in a form) can be lost. If you prefer the gentle
  behaviour, type once:   watch shield hide        The choice is kept in jarvis_update\screenwatch.json
  Speed: the check uses the Windows API (about 2 ms) and runs 4 times a second ("watch interval 0.2" = even faster);
  the shield re-checks the windows every 0.05 s. "watch" tells you whether it uses the fast method or the slow one.

CLAUDE CODE BRIDGE (new in 3.2.0):  when you talk to Jarvis and the request is not one of its local answers, it is
  passed in the background to the installed Claude Code CLI (hidden window) and the reply is pasted here under the
  name JARVIS. It uses only the model Claude Code is configured with; no other model or provider.
  Tools are switched off: a text answer only, no files read, changed or run.
  PRIVACY: the bridge is ON BY DEFAULT. Whatever Jarvis cannot answer locally is sent to Claude Code and therefore
  leaves your computer (it goes to Anthropic's servers). Everything else in Jarvis works locally.
  To switch it off, type:   claude off        (and  claude on  to switch it back on)
  You need Claude Code installed and signed in with your own account: it is a separate product with its own terms.
  Commands:  claude <question>  |  claude status  |  claude on  |  claude off  |  claude model <name>
  "jarvis <question>" does it by itself when the local rules cannot answer.
  IMPLEMENT and HACK never go through the bridge: they keep their own functions.
  The voice stays off at start-up: to hear the answers say  voice on.
  Optional variables:  JARVIS_CLAUDE_MODEL  (fixes the model),  JARVIS_CLAUDE_TIMEOUT  (seconds, default 180),
  JARVIS_CLAUDE_BIN  (path to the CLI),  JARVIS_CLAUDE_ARGS  (extra arguments).
